# 0006. 확정(결제) 요청의 접수번호 — 결제 시도마다 하나 (2단계)
날짜: 2026-09-03 · 단계: 2 · 상태: 결정 · [English](0006-idempotency-key-per-attempt.en.md)
## 문맥
홀드·확정 POST는 `Idempotency-Key`(접수번호)가 필수다. 서버(IdempotencyFilter)는 같은 사용자·같은 키의 첫 응답을 24시간 저장해 그대로 재생하는데, **2xx뿐 아니라 4xx도 저장하고 5xx만 저장하지 않는다.** 또 같은 키의 동시 요청은 막지 않는다. 결제는 돈이 걸린 요청이라 "언제 같은 키를 쓰고 언제 새 키를 만드나"가 곧 이중 결제 방어 규칙이 된다.
## 선택지
- **요청마다 새 키**: 단순하지만 네트워크가 끊겨 결과를 모를 때 재시도가 새 요청이 되어 두 번 결제될 수 있다. 멱등 키를 두는 의미가 없어진다.
- **예매당 키 하나 고정**: 결과를 모를 때의 재시도는 안전하다. 그러나 PG 거절(402)도 저장·재생되므로 사용자가 다시 시도해도 PG를 부르지 않고 거절만 반복한다.
- **결제 시도마다 키 하나** (채택): 키의 수명 = "서버가 아직 판정하지 않은 한 번의 시도". 결과를 모르면(네트워크·타임아웃·5xx) 같은 키, 서버가 판정을 줬으면(성공·거절·상태 오류) 키를 버리고 다음 시도는 새 키.
## 결정
시도마다 하나. 키는 `sessionStorage`에 예매별로 두어 새로고침에도 살아남게 하고, 서버가 판정을 내린 응답(성공·거절·4xx)을 받는 순간 지운다. 5xx는 서버가 저장하지 않으므로 키를 그대로 둔다. 그래서 키가 남아 있다면 뜻은 하나뿐이다 — 결과를 못 받은 시도가 있다는 것. 결과를 모를 때는 같은 키로 바로 재전송하지 않고 **부작용 없는 조회(GET)로 몇 초 먼저 확인**한다. 먼저 보낸 요청이 서버에서 아직 처리 중일 수 있고, 서버가 같은 키의 동시 요청을 막지 않기 때문이다. 5xx도 같은 절차를 탄다 — PG 승인 뒤에 서버가 넘어졌을 수 있어 자동 재전송은 하지 않는다. 분류 규칙은 React 없는 순수 함수(`apps/web/src/lib/confirm-policy.ts`)에 모아 단위 테스트로 고정한다.
## 결과
얻는 것: 연결이 끊긴 결제를 재시도해도 두 번 결제되지 않고, 거절 뒤 재시도는 실제로 PG를 다시 부른다. 잃는 것: 클라이언트가 키 수명을 관리해야 하고(저장소 1칸, 분기 6개), 결과를 모르는 상태가 몇 초 이어지며 그 뒤에는 사용자가 한 번 더 눌러야 한다. 서버 측 동시 요청 방어(같은 키 `SET NX` 선점)와 PG 승인 뒤 서버 오류의 재승인 방지는 각각 4단계 부하 검증, 3단계 payment 분리 때 다시 본다.
